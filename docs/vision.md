# Vision — Personal Cognition Ledger

## 1. Purpose

The purpose of this system is to help an individual **understand, structure, and improve their own thinking and learning over time**.

This is not a productivity tool.  
This is not a timer.  

It is a system for **capturing cognition as it actually happens**.

---

## 2. Core Idea

The system is built around a simple but powerful concept:

> A learning or working session should be captured as a structured unit of intention, activity, evidence, and reflection.

Each session answers four fundamental questions:

- What was I trying to do
- What did I actually do
- What evidence was produced or used
- What did I learn or realize

Over time, these sessions form a **personal cognition ledger**.

---

## 3. What This Is Not

To keep the system focused, it explicitly avoids being:

- a simple time tracking app
- a generic note-taking tool
- a file storage system
- a task manager replacement
- a productivity gamification system

Those tools optimize for convenience.  
This system optimizes for **understanding**.

---

## 4. Long-Term Vision

The long-term goal is to create a system that allows a user to:

- replay past learning sessions with context
- understand patterns in how they learn and work
- identify friction points and inefficiencies
- improve decision-making and skill acquisition
- build a reliable memory of their intellectual work

In other words:

> Turn invisible thinking into structured, inspectable history.

---

## 5. Core Concepts

The system revolves around a few stable concepts:

### Session
A bounded period of focused activity.

### Task (Intention)
What the user planned or intended to do.

### Evidence
What proves or represents what happened:
- files
- notes
- links
- screenshots
- code-related artifacts (future)

### Reflection
What the user concluded after the session.

### Replay
A reconstructed timeline of the session.

---

## 6. Design Philosophy

### Capture Reality, Not Ideal Behavior

The system should record what actually happens, not what was planned perfectly.

---

### Evidence Over Assumption

Do not infer activity if it can be captured.

---

### Structured but Flexible

The system should allow structure without forcing rigid workflows.

---

### Backend First

The system's value comes from its data model and domain logic, not its interface.

---

### Slow Evolution

The system is expected to evolve over a long period.  
Clarity and stability are more important than speed.

---

## 7. Success Criteria (V1)

The system is successful when a user can:

- start and stop a session
- declare what they intend to do
- attach evidence to the session
- review what happened in that session
- write a reflection

No automation, no AI, no advanced UI is required for initial success.

---

## 8. Future Direction (Not Now)

Potential future capabilities include:

- automatic evidence capture (editor, browser, terminal)
- AI-assisted reflection and summarization
- pattern detection across sessions
- learning efficiency analytics
- coding session integration (commits, diffs, logs)

These are explicitly **not part of V1**.

---

## 9. Guiding Principle

If a feature does not help answer:

- What happened
- Why it happened
- What was learned

then it does not belong in the system.

---

## 10. One-Line Summary

A system that turns learning and thinking into a structured, replayable, and improvable history.
