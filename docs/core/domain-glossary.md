# Domain Glossary — Personal Cognition Ledger

## Purpose

This document defines the core terms used in the system.

The goal is consistency.  
Every term should have one clear meaning and should not overlap with others.

---

## Core Concepts

### Session

A bounded period of focused activity.

A session has:
- a start time
- an end time
- a lifecycle state
- associated tasks
- associated evidence
- optional reflection

A session represents **execution**.

---

### Task

A declared intention for what the user plans to do.

Examples:
- practice listening
- read documentation
- implement feature
- debug issue

A task represents **intent**, not execution.

---

### SessionTaskAssignment

The relationship between a session and a task.

A session can have multiple tasks.  
A task can appear in multiple sessions.

---

### EvidenceItem

A piece of proof that something happened during a session.

Examples:
- note
- file
- image
- link
- snippet
- manual checkpoint

This is a **core concept** and should remain flexible.

---

### Artifact

A type of evidence that has a stored representation (file or structured content).

Not all evidence must be an artifact.

---

### EvidenceSource

Where the evidence came from.

Examples:
- manual input
- uploaded file
- external link
- system-generated (future)

---

### Annotation

User-added meaning or interpretation on top of evidence.

Examples:
- highlight
- comment
- note attached to a file
- extracted snippet

Annotation is **not the same as evidence**.

---

### SessionEvent

A recorded event that happens during a session.

Examples:
- session started
- task attached
- evidence added
- annotation created
- session stopped

Used for building timelines and replay.

---

### Timeline

An ordered sequence of events and evidence within a session.

---

### Replay

A reconstructed view of a session based on timeline data.

Replay is **read-only** and derived from other data.

---

### Reflection

A structured summary created after a session.

May include:
- what was learned
- what was difficult
- what is unclear
- next steps

---

### Insight (Future)

A derived understanding based on one or more sessions.

Often generated by analysis or AI in the future.

---

### User

The owner of sessions, tasks, and data.

Even in a single-user system, this concept remains explicit.

---

## Key Distinctions

### Session vs Task

- Session = execution (what actually happened)
- Task = intention (what was planned)

---

### Evidence vs Annotation

- Evidence = proof of activity
- Annotation = interpretation of that proof

---

### Timeline vs Replay

- Timeline = raw ordered data
- Replay = structured view for reading

---

## Rule

If a new feature introduces a new term,  
it must be added here before being used in code.
